# TravelShaper — Running & Testing Guide

## Prerequisites

| Requirement | Version | Notes |
|-------------|---------|-------|
| Python | 3.11+ | Required |
| pip | Any recent | Comes with Python |
| Docker + Docker Compose | Any recent | For containerised run |
| OpenAI API key | — | Required for the agent |
| SerpAPI key | — | Required for flights/hotels/cultural guide |

---

## 1. Local Setup

### 1a. Clone / unzip the project

```bash
unzip travelshaper-complete.zip
cd travelshaper/se-interview-main
```

### 1b. Create and activate a virtual environment

```bash
python3 -m venv .venv
source .venv/bin/activate        # macOS / Linux
# .venv\Scripts\activate         # Windows
```

Your prompt should now show `(.venv)`. All subsequent commands assume the
venv is active.

### 1c. Install Poetry inside the venv

```bash
pip install --upgrade pip
pip install poetry==1.8.2
```

Poetry is now isolated to this venv and will not affect any system-wide
Python installation.

### 1d. Install project dependencies

```bash
# Core dependencies + test runner
poetry install -E dev
```

#### Phoenix tracing packages (optional — for running evals and the Phoenix server locally)

The core tracing packages (`arize-phoenix-otel` and
`openinference-instrumentation-langchain`) are included in `pyproject.toml`
and installed automatically by `poetry install`. For running the Phoenix
server locally and the evaluation pipeline, also install:

```bash
pip install arize-phoenix arize-phoenix-evals
```

These two packages are NOT in `pyproject.toml` because `arize-phoenix` is
the full Phoenix server (with its own FastAPI app, SQLAlchemy, etc.) and
would conflict with TravelShaper's FastAPI. In Docker mode, Phoenix runs
in its own container so these are not needed.

### 1e. Configure environment variables

```bash
cp .env.example .env
```

Open `.env` and fill in your keys:

```
OPENAI_API_KEY=sk-...
SERPAPI_API_KEY=...
PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006/v1/traces
```

`PHOENIX_COLLECTOR_ENDPOINT` is only needed if you are running the Phoenix
tracing stack. Leave the default value — it will be ignored if Phoenix is
not running.

## 2. Running the API Server

### Option A — Local (venv)

```bash
uvicorn api:app --host 0.0.0.0 --port 8000 --reload
```

The API will be available at `http://localhost:8000`.

Verify it is healthy:

```bash
curl http://localhost:8000/health
# → {"status":"ok"}
```

Send a chat message:

```bash
curl -s -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "Plan a trip from SFO to Tokyo in October. I want to save money and I love food."}'
```

### Option B — Docker Compose (recommended for full stack)

Starts TravelShaper **and** Phoenix together:

```bash
docker-compose up --build
```

| Service | URL |
|---------|-----|
| TravelShaper API | http://localhost:8000 |
| Phoenix Tracing UI | http://localhost:6006 |

Stop everything:

```bash
docker-compose down
```

### Option C — Docker only (no Phoenix)

```bash
docker build -t travelshaper .
docker run -p 8000:8000 --env-file .env travelshaper
```

## 3. Running the Tests

### All 14 tests (recommended)

```bash
pytest tests/ -v
```

Expected output: **14 passed** (2 agent structure tests, 8 API/validation tests, 4 tool tests).

> **No API keys are required to run tests.** All external calls are mocked.

### Run a specific test file

```bash
pytest tests/test_tools.py -v
pytest tests/test_agent.py -v
pytest tests/test_api.py -v
```

### Run a single test by name

```bash
pytest tests/test_tools.py::test_search_flights_formats_results -v
```

## 4. Generating Phoenix Traces

Traces are generated by running real queries against the live API. Do this
**after** starting the full Docker Compose stack (Step 2, Option B).

### Run all 10 trace queries automatically

```bash
chmod +x run_traces.sh
./run_traces.sh
```

You can optionally pass a custom base URL:

```bash
./run_traces.sh http://localhost:8000
```

The script runs 10 queries covering every tool combination — flights,
hotels, cultural guide, DuckDuckGo search, budget vs. full-experience
mode, partial inputs, and edge cases. Each query is followed by a 2-second
pause to avoid rate limiting.

### Run a single query manually

```bash
curl -s -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "What should I know before visiting Japan?"}'
```

View traces in the Phoenix UI at **http://localhost:6006** after running queries.

## 5. Running Evaluations

Evaluations use Phoenix's LLM-as-judge pipeline to score traces for user
frustration and tool usage correctness.

### Prerequisites

- Phoenix packages installed (see Step 1c above)
- Phoenix is running: `docker-compose up`
- At least some traces exist: run `./run_traces.sh` first

### Run evaluations

```bash
python -m evaluations.run_evals
```

Expected output (numbers will vary):

```
Found 10 traces. Running evaluations...
User Frustration: 1/10 frustrated (10%)
Tool Correctness: 9/10 correct (90%)
Created 'frustrated_interactions' dataset with 1 examples.
Evaluations complete. View results in Phoenix UI at http://localhost:6006
```

Results are logged back to Phoenix and visible in the **Evaluations** tab
of the Phoenix UI.

## 8. Troubleshooting

**`SERPAPI_API_KEY is not set` error**
The agent is running live (not in tests). Copy `.env.example` to `.env`
and add your SerpAPI key, then restart the server.

**`OPENAI_API_KEY` auth error**
Your OpenAI key is missing or invalid. Check your `.env` file.

**Tests fail to collect**
Make sure you are running from the project root (`se-interview-main/`) with
the venv active (`source .venv/bin/activate`). Then run `poetry run pytest tests/ -v`.

**Phoenix UI shows no traces**
Traces are only generated when real queries hit the live API. Run
`./run_traces.sh` after starting the full `docker-compose up` stack.

**`ModuleNotFoundError: No module named 'phoenix'`**
The tracing client packages are installed by `poetry install`. If you need
the Phoenix server or eval runner locally, install them with pip:
`pip install arize-phoenix arize-phoenix-evals`

**Poetry creates a nested virtualenv instead of using the active venv**
Run this once in the project directory, then reinstall:
```bash
poetry config virtualenvs.create false --local
poetry install
```

**Docker build fails at `poetry install`**
A `poetry.lock` file is required for reproducible builds. Generate it
with `poetry lock` and commit it before building the image.
